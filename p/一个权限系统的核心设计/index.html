一个权限系统的核心设计

2024-05-17 15:37:04

# 概述

世界是由0和1组成的，权限亦如是。

一个人在接近一个东西的时候，这个东西可能是调接口、可能是取钱、可能是听音乐看要不要会员，结果要么是可以，要么是不可以。接口通或不通，钱能不能取出来，音乐能不能听，这在表面上是两个不同结果的呈现。

权限在很多情景下，是简单的、易理解的。

你在银行存了2000块钱，理论上除了你，没有人能操作这笔钱。

你的微信账号，理论上除了你，没有人可以登录这个账号。

你的朋友圈设置了某某可见，理论上，除了所指定可见的用户，其余人都不可见。

权限在某些情况下也可能是复杂的。

例如公司设置，在每周六的19-21点之间，A部门的B小组下的全体成员，无法使用某系统的个别接口。

假如公司的组织和个人，以及小组和角色的关系是一颗大的权限树，这棵树上的各个节点，就是所谓的关系。

个人身上可能由多个角色或类别或组别构成，个人可能会根据权限的优先级，继承父级的权限，当一个未明确授予拒绝或允许权限的个人，试图查看一份文件时，这份文件时默认允许查看呢？还是拒绝查看呢？

权限的世界可以是很复杂的，但也是有趣的。

# 权限设计模型（RBAC和ABAC）

基于角色的访问控制（RBAC）和基于属性的访问控制（ABAC）是控制认证过程和授权用户的两种方法。RBAC 和 ABAC 之间的主要区别是 RBAC 基于用户角色提供对资源或信息的访问，而 ABAC 基于用户、环境或资源属性提供访问权限。从本质上讲，当考虑 RBAC 与 ABAC 时，RBAC 控制整个组织的广泛访问，而 ABAC 则采取细粒度的方法。

# RBAC

迄今为止最为普及的权限设计模型是RBAC模型,基于角色的访问控制（Role-Based Access Control)

RBAC事先会在系统中定义出不同的角色，不同的角色拥有不同的权限，一个角色实际上就是一组权限的集合。而系统的所有用户都会被分配到不同的角色中，一个用户可能拥有多个角色。使用RBAC可以极大地简化权限的管理。

# ABAC

在 ABAC 中，一个操作是否被允许是基于对象、资源、操作和环境信息共同动态计算决定的。

  • 对象：对象是当前请求访问资源的用户。用户的属性包括ID，个人资源，角色，部门和组织成员身份等；
  • 资源：资源是当前访问用户要访问的资产或对象（例如文件，数据，服务器，甚至API）。资源属性包含文件的创建日期，文件所有者，文件名和类型以及数据敏感性等等；
  • 操作：操作是用户试图对资源进行的操作。常见的操作包括“读取”，“写入”，“编辑”，“复制”和“删除”；
  • 环境：环境是每个访问请求的上下文。环境属性包含访问尝试的时间和位置，对象的设备，通信协议和加密强度等。

# 2. GrantedPrivilege

定义授予的权限，以及权限运算
权限由表示权限和掩码的两个整数组成，其中：

a. 权限的位表示是否拥有权限。某个位为1表示拥有对应的权限，0表示不拥有。
b. 掩码的位表示授予状态。某个位为1表示此项权限为明确授予，0表示未明确授予

最终权限为：权限 and 掩码

# 3. Acl

定义权限适用规则.
Acl由如下几项组成：

项说明
scope范围: 1. 当前节点；2. 包括自身和直接级；3. 自身和全部下级
allStaff是否适用于所有用户
users适用的特定用户
groups适用的特定组
组合选取由部门和职位以及用户特殊属性进行选取的适用范围
- departments部门，来自HR定义
- classifies职位，来自HR定义
- features用户属性，包括：试用期员工和实习员工
- and部门和职位的关系是否是交集

# 二、权限设置

  1. 权限设置在任意的目录或者文件节点之上。
  2. 设置在文件上的权限只对当前文件有关，因此
  1. 只应该设置文档权限
  2. 只应该设置范围为当前
  1. 目录上设置的文件权限对目录下的文件有效。
  2. 目录或者文件上可以设置取消继承标示，表示当前目录或文件之前的权限规则无效。

# 三、具体过程

# 1. 计算对某个节点(目录或者文件)起作用的ACL

  1. 查询节点以及上级节点上所设置的所有ACL
  2. 查询节点以及上级节点上有禁止继承标示的节点
  3. 抹除禁止继承节点影响的ACL的权限
  4. 根据ACL的作用范围，计算是否适用当前节点，得到实际有效的ACL

# 2. 合并ACL

  1. 分为允许和拒绝
  2. 是否为全部用户允许
  3. 合并用户和组别
  4. 判别部门和职位以及特征的组合是否需要用Hash方式生成复杂条件
  1. 当同时存在部门和职位时
  2. 当部门或者部门之一存在，且不包含全部的特征（实习生，试用期）
  1. 将拒绝的条件从允许条件里删除

# 3. 匹配ACL，获取授权

分为：合并和非合并

# 4. 计算ACL影响的文件和目录

此处为避免遍历目录和文件，适用凑条件的方式生成SQL语句进行查询。

需要的条件：

  1. ACL
  2. 权限掩码
  3. 断路目录

生成FileQueryParam

属性说明
equalList= path
likeListlike path/%
likeFileListlike path/% and type = file
likeDirListlike path/% and type = dir
similar1FileListmatch path/[0-9]+ and type = file
similar1DirListmatch path/[0-9]+ and type = dir
similar2FileListmatch path(/[0-9]+){2} and type = file

如果存在断路目录，则对应条件加上：and not like path/%

简要过程：

  1. 设置在文件上的权限只对文件有效，因此生成：file.name = path

  2. 设置在目录上的权限

a. 当前及全部下级，

目录：dir.name = path 和 dir.name like path/%
文件：file.name = path 和 file.name like path/%

b. 当前节点范围，

目录：dir.name = path
文件：file.name match path/[0-9]+

c. 当前及直接下级范围，

目录：dir.name = path 和 dir.name match path/[0-9]+
文件：file.name match path/[0-9]+ 和 file.name match path(/[0-9]+){2}
